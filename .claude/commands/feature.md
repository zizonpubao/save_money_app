구현할 기능: **$ARGUMENTS**

다음 순서로 진행한다. 각 단계를 건너뛰지 않는다.

## 1. 범위 확정
- `docs/PRD.md` 에서 `$ARGUMENTS` 에 해당하는 부분을 찾아 요구사항을 3~7줄로 정리한다
- 단계 이름(M2 등)만 주어졌으면 그 단계 전체가 범위다
- PRD에 없거나 모호한 부분은 **구현 전에** 사용자에게 한 번에 묻는다. 사소한 건 알아서 정하고 나중에 보고

## 2. 구현
`expo-builder` 에이전트에게 위 요구사항을 넘겨 구현시킨다. 넘길 때 다음을 반드시 포함:
- 정리한 요구사항
- 사용자가 답한 결정 사항
- "완료 보고 형식대로 보고할 것"

## 3. 리뷰
구현이 끝나면 `code-reviewer` 에이전트에게 `git diff` 기준으로 리뷰시킨다.

## 4. 수정
리뷰에 🔴 또는 🟠 항목이 있으면 `expo-builder` 에게 그 목록을 넘겨 고치게 하고, 다시 `code-reviewer` 에게 확인시킨다. 최대 2회 반복. 그래도 남으면 사용자에게 보고하고 판단을 맡긴다.

## 4.5 테스트
리뷰가 "머지 가능"이면 `qa-tester` 에이전트에게 이번 기능의 테스트를 작성시킨다 (DB 쿼리·마이그레이션은 sql.js 모킹, 순수 함수, 훅, 컴포넌트). 🔴 버그가 보고되면 `expo-builder` 에게 넘겨 고치고 재실행. 통과하면 다음으로.

## 5. 마무리
- `/check` 와 동일하게 `npx tsc --noEmit && npx expo lint && npx jest` 실행
- 통과하면 커밋: `feat: <기능명>`
- 커밋 후 `dashboard-keeper` 에게 검사 결과·커밋·변경 파일을 넘겨 현황판 갱신 (백그라운드)
- 사용자에게 최종 보고:
  - 무엇이 됐는지 (3줄 이내)
  - **아이폰 Expo Go에서 직접 눌러봐야 할 것** (체크리스트)
  - 다음 단계 제안 (PRD 순서상 다음 M)
